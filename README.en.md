# dsh-desktop-acrylic

[中文](README.md) · **English**

Tokyo Night themes for [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (DSH) Desktop —
two themes (dark and light), frosted panels, and a monospace font picker.

Both skins are **real themes registered into the built-in theme runtime** (`ctx.theme.register`), so
switching a theme switches the runtime preference itself — no attribute toggles, no after-the-fact CSS
overrides.

## Features

| Feature | How it works | Values |
| --- | --- | --- |
| Themes: Tokyo Night dark / light | Skin tokens (static ramp + alias ramp + component + syntax), 180 tokens each | dark base `#1a1b26`; light base near-white (`#e7e8ee` → `#eff1f6` family) |
| Icons follow the theme | The shell paints icons with `currentColor` and ships no icon-specific tokens, so icons follow `--dsw-alias-label-*` / `--dsw-alias-brand-primary` | nothing to configure |
| Canvas transparency | Background-family tokens carry alpha | dark `0.10` (90% transparent); light `0.30` |
| Material base | A soft blue/purple/cyan field built from the palette, pinned to the bottom layer and pre-blurred | strength dark 30% / light 24%, `blur(28px)` |
| Menus, popovers, floating surfaces | The skin ships `--dsw-menu-backdrop-filter`, applied by the shell's own material path | `blur(24px) saturate(1.15)` |
| Dialogs (the settings window) | Frosted panel: positioned dialogs use `isolation` + an absolutely positioned `::before`; **static** ones (common for a settings window) get the blur on the element itself, after excluding dialogs that contain `position: fixed` descendants | fill `rgba(…, 0.75)` (25% transparent) + `blur(30px)` |
| Dialog backdrop mask | The dim overlay behind an open modal gets a `backdrop-filter`, so the interface shows through frosted; native `<dialog>` elements get `::backdrop`; disabled together with the blur layer under `prefers-reduced-transparency` | `blur(12px) saturate(1.1)` (`--dwa-mask-blur`) |
| Workspace sidebar | Uniform grain (pure `background-image`, no direction, no edges) | dark 6% / light 14% (perception is asymmetric, so the values differ) |
| Cards and tables (genui) | The card library's own `--tv-*` palette is bridged to our alias tokens | 22 bridges: surfaces, interaction, text, icons, borders |
| Native widgets | `color-scheme` follows the theme | scrollbars, checkboxes and friends follow along |
| Fonts | Two searchable pickers (UI font / code font) listing **monospace families installed on this machine**, patched variants included | see "Font detection" below |

Everything is declared in `src/theme.mjs`: `ACRYLIC` (blur radii), `surfaceTable` (surfaces and
alphas), `MONO_FONTS` / `MONO_FONT_BASES` / `MONO_FONT_SUFFIXES` (font data). The stylesheets are
generated by the build script.

## Install

```sh
# from GitHub
dsh plugin --profile desktop add github:LeoLee0097/dsh-desktop-acrylic

# from a local directory (-w is required: the profile directory is a pnpm workspace root)
dsh plugin --profile desktop add -w /absolute/path/to/dsh-desktop-acrylic
```

Quit DSH Desktop **completely** and start it again. After that, reloading the renderer alone is enough
to pick up a new client bundle.

> Note: **changes to the host half (`lib/index.js`) only take effect after the process restarts**,
> because its route table is registered at startup. The client half (`lib/client.js`) and the data
> tables only need a renderer reload. This distinction once caused a "I changed it but it 404s"
> misdiagnosis, which is why it is spelled out here.

## Usage

**Settings → General → "Tokyo Night theme"**:

- **Theme**: dark / light / default — applies immediately;
- **Acrylic**: blur on / blur off — turning it off removes the blur but keeps the theme;
- **UI font / code font**: one searchable picker each, applied on selection, with "restore default";
- **Diagnostics line**: `preference · computed bg-base · chrome on/off · hosts armed/candidates · frost n · panels n`.

`bg-base` is read back with `getComputedStyle(document.body)`, i.e. the value the browser actually
resolved — that is how you tell "the theme landed in the cascade" from "it just looks unchanged".

### Font detection

The browser is **not allowed** to enumerate installed fonts, so the list is built from two sources:

1. **Renderer probing** (always available): candidate names come from `MONO_FONT_BASES` ×
   `MONO_FONT_SUFFIXES` (42 bases × 6 suffixes = 252 probes; suffixes are `NF`, `NFM`, `Nerd Font`,
   `Nerd Font Mono`, `PL`). A candidate counts as present when its text metrics differ from all three
   fallbacks under a canvas measurement.
2. **Host directory scan** (when the route is available): reads the font directories and parses each
   file's `name` table (family) and `post` table (`isFixedPitch`, the format's own monospace flag), so
   families the catalog never guessed — CJK monospace among them — are found too.

The union of both is used. The `fontSource` diagnostic reports `probe` / `host` / `host+probe`, and
`fontCount` is the number of entries.

```sh
node scripts/check-fonts.mjs          # print what the host scan found (monospace list)
node scripts/check-fonts.mjs --all    # also print every family
```

```sh
node scripts/build.mjs     # or npm run build
```

The build refuses to write anything unless four groups of checks pass:

1. **Placeholders** are all substituted, with none left over;
2. **Skins** agree on count / id / colour scheme, default skin and locale dictionaries, and the font
   data tables are non-empty;
3. **Token values** match a conservative grammar (`#hex`, `rgb(a)`, `color-mix`, `blur(..) saturate(..)`,
   `transparent`, `<n>px`, or a `var(--dsw-…)` pointing at one of our own alias tokens) and contain no
   braces or semicolons;
4. **CSS safety**: blur only ever lives on a `::before` layer, frosted panels must carry an opaque fill
   token, and no rule gives a layout container a filter or a position.

## Diagnostics

The plugin reports its live state to a host route, which writes `~/.dsh/dark-acrylic-state.json`:

```sh
curl http://127.0.0.1:<port>/dark-acrylic/state     # state and live report
curl http://127.0.0.1:<port>/dark-acrylic/fonts     # installed font catalog (host scan)
```

```json
{
  "version": 2,
  "plugin": "tokyo-night-theme",
  "chosen": "tokyo-night",
  "acrylic": true,
  "preference": "tokyo-night",
  "chrome": true,
  "hosts": 0,
  "hostStats": { "matched": 23, "armed": 0, "skipped": 23 },
  "frost": 1,
  "panels": 1,
  "masks": 1,
  "fontSource": "probe",
  "fontCount": 18,
  "computed": {
    "bgBase": "rgba(22, 22, 30, 0.1)",
    "sidebar": "rgba(15, 16, 23, 0.1)",
    "menuBlur": "blur(24px) saturate(1.15)"
  },
  "instance": "…",
  "at": "…"
}
```

`panels` counts the dialogs currently carrying the frosted panel, and `panelDebug` states *why* each
dialog was armed or skipped — `div.… 900x600 → flat`, `→ positioned`, `→ skip(static, fixed=3)` or
`→ skip(small)`. When a dialog has no effect, that line is the first thing to read.

`masks` counts how many backdrop masks behind open dialogs were frosted, and `maskDebug` records the
outcome — `div.… → mask` (hit) or `div.… → no-mask` (no viewport-sized fixed/absolute parent or
sibling matched; a native `<dialog>` still gets its `::backdrop` rule in that case). When the
background behind a dialog is not frosted, that line is the first thing to read.

`hosts` and `hostStats` explain "why is there no frost here": `matched` is the number of candidate
containers, `armed` how many actually received a blur layer. Layout columns are usually static
elements, so being rejected by the guard is the expected outcome, not a failure.

## Pitfalls (each one is enforced by the build or documented in the source)

1. **Never put `backdrop-filter` on a layout container.** It turns the element into a containing block
   for `position: fixed` descendants, and the shell pins its sidebar toggle and new-session button
   exactly that way — the controls re-anchor and disappear.
2. **Never place an absolutely positioned blur layer inside a static container.** The pseudo-element
   escapes to the nearest positioned ancestor, covers the viewport and blurs the entire interface,
   text included — this was the cause of the early "text does not render" regressions. The blur layer
   is therefore only mounted on containers that are *already* positioned.
3. **Font variables must not reference themselves.** `--dsw-font-family: X, var(--dsw-font-family)` is a
   CSS cycle: the variable and every `font:` shorthand reading it become invalid.
4. **The settings slot hands a row exactly three things**: `t` (from `locale`), `useStore` (from
   `store`) and the return value of `inject(actions)`. There is no ambient theme service on props.
5. **"Transparent" and "frosted" are different things.** Alpha gives transparency; frost is
   convolution of what is behind. There must be *something* behind to convolve, which is what the
   material base layer is for.
6. **Native widgets ignore page styling and scroll unreliably.** A `<select>` popup is an OS-level
   surface: only `color-scheme` reaches it, and wheel behaviour in a long list is not dependable. A
   controllable dropdown has to be drawn by the app.
7. **A directional texture applied to a single column becomes a seam.** A top-down sheen plus a 1px
   inner highlight drew a bright line along the top edge of the sidebar. Uniform grain has no edges.
8. **Light and dark perception is asymmetric.** The same grain strength is obvious as light dots on a
   dark base and nearly invisible as dark dots on a light base, so matching parameters cannot share a
   single value.
9. **A dialog is not necessarily a positioned element.** If the blur only ever lives on a `::before`,
   a static panel (which is what this settings window turned out to be) is skipped by the guard
   entirely and simply shows no effect. Covering both structures needs a fallback that puts the blur on
   the element itself — after excluding dialogs with `position: fixed` descendants, which are the ones
   a filter would re-anchor.

## Known limits

**On Windows the main window does not request a window material** (only the welcome window does; on
macOS the main window uses `vibrancy: "sidebar"`). What this plugin can therefore deliver on Windows
is: the palette, translucent surfaces, frost on panels and popovers, and an in-app material colour
field. Letting the desktop show through requires a small change in the desktop app's main process —
see [docs/desktop-window-material.md](docs/desktop-window-material.md).

With `prefers-reduced-transparency: reduce` the blur layers are disabled automatically.

  `color-scheme` follows the theme for native widgets.

- **0.6.x** — Light palette brightened, desaturated and darkened for text; sidebar and canvas share one

  dialogs became genuine frosted panels (25% transparency + 30px blur).
- **0.5.x** — Static frosted texture for surfaces that cannot be blurred, dialog geometry experiments
  and subsequent tightening, `frost` / `frostTargets` diagnostics.
- **0.4.x** — The material base layer (soft colour field) fixed "there is nothing to blur"; strength and
  pre-blur tuning; the menu material radius was decoupled from the chrome layer.
- **0.3.x** — Rebuilt around "implement it as a theme": two real skins + a settings row (theme / font) +
  the acrylic layer; staged the positioning failure surface; hardened the safety mode (opaque page
  base, readability-first alpha, failure isolation, build-time validation).
- **0.1.0 - 0.2.x** — Early versions: skin registration, settings row, durable toggles, transparency
  levels and the regressions that came with them.
